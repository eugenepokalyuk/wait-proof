# Я тебя жду

Огромный тумблер на двоих, который раз и навсегда решает, кто кого ждал.
Ручка на имени — этого человека ждут. Таймер идёт на сервере, второй
получает пуш, из ожиданий складывается счёт за неделю, месяц и всё время.

**Приложение:** https://eugenepokalyuk.github.io/wait-proof/
**API и админка:** https://168-222-142-117.sslip.io/api/v1 · `/admin/`

Техническое задание — [TZ.md](TZ.md).

| Папка     | Что там                                                        |
| --------- | -------------------------------------------------------------- |
| `web/`    | PWA: Next.js 16 (static export) + React 19 + RTK Query + SCSS Modules + framer-motion |
| `api/`    | Django 5.1 + DRF + SimpleJWT, PostgreSQL, Web Push              |
| `deploy/` | compose для сервера, скрипт выкатки, бэкап, блок nginx для Формы |

## Запуск локально

```bash
# бэкенд — localhost:8000, SQLite
cd api
python3.12 -m venv .venv && source .venv/bin/activate
make install
cp .env.example .env
make migrate
make admin            # суперпользователь для /admin
make runserver

# фронт — localhost:3000
cd web
npm install
cp .env.example .env.local
npm run dev
```

Пуши локально: `make vapid` в `api/`, ключи — в `api/.env`. Service worker
и Web Push работают на `localhost` без https.

Тесты бэкенда: `make test`. Фронт проверяется сборкой: `npm run build`
прогоняет TypeScript.

## Деплой

Всё — только через GitHub. Напрямую на сервер ничего не копируется.

- **Фронт.** Мерж в `main` с изменениями в `web/` → GitHub Actions собирает
  статику и публикует на GitHub Pages (`.github/workflows/deploy-web.yml`).
  Можно запустить руками: вкладка Actions → Deploy to GitHub Pages → Run
  workflow. Разово: **Settings → Pages → Source: GitHub Actions**.
- **Бэкенд.** Мерж в `main` с изменениями в `api/` или `deploy/` → Actions
  прогоняет тесты, собирает образ в GHCR и выкатывает его на сервер по ssh
  (`.github/workflows/deploy-api.yml`). Сборки на сервере нет.
- **CI** на пул-реквестах: сборка фронта, проверка экспорта, тесты и сборка
  образа бэкенда (`.github/workflows/ci.yml`).

Выкатка на сервер включается переменной репозитория `DEPLOY_ENABLED=true`,
когда сервер подготовлен и заведены секреты `DEPLOY_SSH_KEY`, `DEPLOY_HOST`,
`DEPLOY_KNOWN_HOSTS`. До этого образ собирается, а выкатка пропускается.

### Сервер

- свои контейнеры (`wait-proof-*`), своя база, лимиты памяти на каждый;
- наружу не публикуется ни один порт — API отдаёт nginx Формы через общую
  сеть `edge`;
- в nginx Формы прокси через переменную и `resolver`, сертификат по пути,
  где файл есть всегда, — nginx стартует при любом состоянии нашего проекта;
- деплой чистит только образы с меткой `project=wait-proof`.

Разовая подготовка — [deploy/bootstrap.md](deploy/bootstrap.md), правка
Формы — [deploy/forma/PR.md](deploy/forma/PR.md).

## Как устроено

- **Источник правды — сервер.** Клиент показывает таймер от `started_at`
  с поправкой на часы телефона (`server_time` в каждом ответе).
- **Щелчок оптимистичный.** Ручка уезжает сразу; у таймера есть `version`,
  одновременный щелчок с двух телефонов получает 409 и актуальное положение.
- **Отмена 10 секунд.** Отменённое ожидание не удаляется, а помечается и не
  идёт в счёт; закрытое щелчком — открывается обратно.
- **Пуши на любое переключение** — обоим участникам на все устройства,
  кроме того, с которого щёлкнули (`X-Device-Id`).
- **Живость без WebSocket.** Экран таймера опрашивает сервер раз в 5 секунд,
  пуш будит открытое приложение сразу через service worker.
- **Периодика** — контейнер `tick`: напоминания, автозакрытие забытых
  ожиданий через 12 часов, чистка.
- **iPhone.** Web Push работает только у приложения на экране «Домой»
  (iOS 16.4+), и у него своё хранилище — войти нужно заново. Экран
  `/install/` это объясняет.

## Админка

`/admin/` — пользователи (там же «забыл пароль»: новый пароль задаёт
администратор), таймеры с действием «Снять ожидание», ожидания (правка
длительности и «идёт в счёт» — так разбирают спор), дружба, пуш-подписки с
проверочной отправкой, журнал пушей, настройки с текстами уведомлений.
