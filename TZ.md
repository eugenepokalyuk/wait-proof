# «Я тебя жду» — техническое задание

Версия 1.3 · 2026-09-16

## 1. Зачем это

Пара постоянно спорит, кто кого ждал. Приложение решает спор фактами: в
момент ожидания один из двоих щёлкает огромный тумблер, таймер идёт на
сервере, второй получает пуш, а вся история копится в статистику «кто кого
сколько ждал».

Главный экран — один тумблер на три положения:

```
   ОНА                  никто                  ОН
 ┌──────────────────────────────────────────────────┐
 │ ●                                                │   ← тумблер на «Она»:
 └──────────────────────────────────────────────────┘     он ждёт её
                   ждёт уже 00:23:41
```

- **Слева** — «Она» (подпись меняется, например «Катя»).
- **Справа** — «Он» (подпись меняется).
- **Тумблер на имени** = этого человека ждут. На «Она» — он ждёт её.
- **По центру** = никто никого не ждёт, таймер снят.

Принципы, которые важнее любой фичи:

1. **Быстро.** Щелчок тумблера отзывается мгновенно, без спиннеров.
2. **Приятно.** Живые, физичные анимации на framer-motion.
3. **Ничего лишнего.** Каждый экран, зависимость и килобайт должны
   оправдывать своё место. Если сомневаешься — не добавляй.
4. **Таймер не теряется.** Источник правды — сервер. Перезагрузка,
   закрытая вкладка, смена телефона — ожидание продолжается.

## 3. Роли и термины

- **Пользователь** — человек с кабинетом, вход по почте и паролю.
- **Друг** — пользователь, с которым установлена дружба (взаимная).
- **Таймер** — доска на двоих друзей: левая сторона, правая сторона,
  подписи, текущее положение тумблера. Один таймер на пару друзей.
- **Ожидание** — один эпизод: кого ждали, кто ждал, когда началось и
  кончилось, кто включил и кто снял. Из ожиданий строится история и счёт.
- **Администратор** — сотрудник с доступом в Django-админку.

## 4. Пользовательские сценарии

### 4.1. Регистрация и вход — почта + пароль

Почтового ящика для отправки писем пока нет, поэтому в первой версии
**письма не отправляются вообще**: ни кодов, ни подтверждений, ни
приглашений.

- **Регистрация** — почта, пароль, имя → `POST /auth/register` → пара JWT,
  пользователь сразу внутри. Почта не подтверждается.
- **Вход** — почта и пароль → `POST /auth/login` → пара JWT.
- **Пароль** — от 8 символов, проверки Django `AUTH_PASSWORD_VALIDATORS`
  (не слишком простой, не совпадает с почтой). Хэш — стандартный Django
  PBKDF2, без лишних библиотек.
- **Смена пароля** — в профиле, со старым паролем.
- **Забыл пароль** — на экране входа подсказка «Напиши администратору»;
  администратор задаёт новый пароль в админке (штатная форма Django).
- На экране одна форма с переключателем «Вход / Регистрация». Поля с
  правильными `autocomplete` (`email`, `current-password`, `new-password`),
  чтобы iOS и Android предложили сохранить пароль в связку ключей — это
  важно для приложения на экране «Домой»: у него отдельное хранилище от
  Safari, и войти там придётся заново, а связка ключей подставит пароль.
- Ошибка входа всегда одна — «Неверная почта или пароль», без уточнения,
  что именно неверно.

Сессия: access 30 минут, refresh 60 дней с ротацией и blacklist
(`rest_framework_simplejwt.token_blacklist`). Пара «ни разу не выходила из
приложения полгода» — нормальный сценарий, разлогинивать её нельзя. При
смене пароля все refresh-токены пользователя, кроме текущего, отзываются.

**Когда появится ящик**: добавить подтверждение почты и сброс пароля кодом
на почту (модель `LoginCode` из k30-api). Модель пользователя это
предусматривает заранее — поле `email_verified`, сейчас всегда `false`.

### 4.2. Друзья

Два способа:

- **Ссылка-приглашение.** В профиле у каждого есть личный код
  (8 символов Crockford Base32, как коды в k30) и ссылка
  `…/invite/?code=K7M2QX9D`. Открыл ссылку → (вошёл, если нужно) →
  дружба создаётся **сразу**: владелец сам поделился ссылкой, это и есть
  согласие. Код можно перевыпустить — старая ссылка перестаёт работать.
  Кнопка «Поделиться» — `navigator.share`, фолбэк — копирование.
- **По почте.** Ввёл почту друга → заявка. Друг видит её во входящих и
  принимает/отклоняет. Если почта ещё не зарегистрирована — заявка
  тихо ждёт и появится у человека, когда он зарегистрируется (писем нет).
  Ответ API одинаковый в обоих случаях.

Можно: отменить исходящую заявку, отклонить входящую, удалить друга
(общий таймер уходит в архив, история сохраняется).

### 4.3. Создание таймера

С экрана друга «Создать таймер»:

- кто слева, кто справа (по умолчанию слева друг, справа я; есть
  «Поменять местами»);
- подписи сторон — по умолчанию имена из профилей, можно «Она» / «Он» или
  что угодно до 20 символов.

Оба участника видят **одинаковую** раскладку: «лево» у всех одно, иначе
спор просто переедет в «а у меня она справа».

Если у пользователя ровно один таймер, приложение открывается сразу на
нём, минуя список.

### 4.4. Тумблер

| Действие                         | Результат                                          |
| -------------------------------- | -------------------------------------------------- |
| Тап по левой половине / имени    | Тумблер на левом имени, стартует ожидание           |
| Тап по правой половине / имени   | То же для правого                                  |
| Свайп ручки и отпускание         | Ручка прилипает к ближайшей из трёх позиций         |
| Тап по центру / кнопка «Дождались» | Ожидание закрывается, таймер снят                 |
| Слева сразу направо              | Текущее ожидание закрывается, открывается новое     |

- Щёлкать может **любой из двоих, в любую сторону** — ограничений нет.
  В истории видно, кто щёлкнул.
- После каждого щелчка 10 секунд висит тост **«Отменить»**. Отмена
  удаляет только что созданное ожидание целиком (промах пальцем не должен
  попасть в статистику). Отменить может только тот, кто щёлкнул.
- **Автозакрытие.** Забытое ожидание закрывается само через 12 часов
  (настройка в админке) с пометкой «закрыто автоматически» и в статистику
  не идёт.
- Одновременные щелчки: у таймера есть `version`. Клиент шлёт версию,
  которую видел; если за это время второй уже щёлкнул — сервер отвечает
  409 с актуальным состоянием, клиент откатывает ручку туда и показывает
  тост «Катя уже переключила».

Под тумблером — большой таймер `ЧЧ:ММ:СС` («ждёт уже 00:23:41») и строка
«с 18:40». В центральном положении — «Никто никого не ждёт» и счёт недели.

### 4.5. Уведомления

**Любое переключение тумблера — пуш.** Его получают оба участника на все
свои устройства, кроме того устройства, с которого щёлкнули (там результат
и так на экране). Если Дима щёлкнул с телефона, пуш придёт Кате и на
Димин планшет. Отличить устройство помогает `device_id`: случайный UUID,
который клиент создаёт один раз, хранит в `localStorage` и отправляет
при подписке на пуши и в заголовке `X-Device-Id` при щелчке.

| Событие                      | Текст (редактируется в админке)                     |
| ---------------------------- | --------------------------------------------------- |
| Ожидание началось            | «Дима ждёт Катю ⏳» · «с 18:40, включил(а) Дима»      |
| Сторона сменилась            | «Теперь Катя ждёт Диму» · «Дима ждал 12 мин»         |
| Ожидание снято               | «Дождались 🎉» · «Дима ждал Катю 23 мин»             |
| Щелчок отменён               | «Отменено» · «Никто никого не ждёт»                  |
| Напоминание (тому, кого ждут)| «Дима ждёт уже 30 мин»                              |
| Автозакрытие (обоим)         | «Ожидание закрыто автоматически»                     |
| Заявка в друзья / принята (адресату) | «Катя хочет добавить тебя в друзья»        |

Тексты с именами участников, а не «ты/тебя»: пуш приходит и тому, кто
щёлкнул (на другие устройства), и формулировка должна быть верна для обоих.

- Напоминания: каждые N минут, N в настройках таймера — выкл / 15 / 30 / 60,
  по умолчанию 15.
- Уведомления одного таймера схлопываются (`tag: timer-<id>`,
  `renotify: true`) — в шторке не копится простыня.
- Тап по пушу открывает этот таймер (если приложение открыто — фокус на
  окно, без новой вкладки).
- Пуши о переключениях в приложении не отключаются — это суть продукта.
  В настройках пользователя два переключателя: напоминания и друзья.
  Заглушить всё целиком можно системными настройками телефона.

**Ограничения платформ, отражаются в интерфейсе:**

- **iOS/iPadOS** — Web Push работает **только** из приложения, добавленного
  на экран «Домой», iOS 16.4+. В Safari показываем экран-инструкцию
  «Поделиться → На экран «Домой»» с картинками. Внутри установленного
  приложения нужно войти заново (отдельное хранилище) — предупреждаем об
  этом на экране инструкции.
- **Android / десктоп Chrome, Edge, Firefox** — пуши работают и в браузере;
  на Android предлагаем установку через `beforeinstallprompt`.
- Запрос разрешения — **только по нажатию** кнопки «Включить уведомления»
  (Safari иначе отказывает, а внезапный системный диалог раздражает).
- Если разрешение отклонено — показываем, как включить в настройках, и
  больше не дёргаем.

### 4.6. История и счёт

Экран таймера → «История»:

- **Счёт** за неделю / месяц / всё время: сколько суммарно ждал каждый,
  сколько раз, в среднем, рекорд. Крупно: «Дима ждал Катю 3 ч 12 мин,
  Катя Диму — 47 мин».
- **Лента ожиданий** с подгрузкой при прокрутке (cursor-пагинация): дата,
  кто кого ждал, длительность, кто включил, кто снял.
- Отменённые и автозакрытые в счёт не входят; автозакрытые видны в ленте
  серым.
- Редактировать историю пользователи не могут. Исправляет администратор в
  админке — иначе спор переедет в войну правок.

### 4.7. Профиль и настройки

Имя, почта (только чтение), смена пароля, личный код и ссылка-приглашение,
настройки уведомлений, список устройств с пушами (удалить устройство),
«Выйти», «Удалить аккаунт» (с вводом пароля).

## 5. Экраны фронта

Статический экспорт не умеет динамические сегменты без списка id на этапе
сборки, поэтому идентификаторы — в query-параметрах.

| Маршрут                  | Экран                                             |
| ------------------------ | ------------------------------------------------- |
| `/login/`                | Вход / регистрация (почта, пароль, имя)            |
| `/`                      | Единственный таймер или список таймеров            |
| `/timer/?id=12`          | Тумблер (главный экран)                            |
| `/timer/history/?id=12`  | Счёт и лента                                       |
| `/timer/settings/?id=12` | Подписи, стороны, напоминания, архив              |
| `/friends/`              | Друзья, входящие/исходящие заявки, «Добавить»     |
| `/invite/?code=…`        | Приём приглашения                                  |
| `/profile/`              | Профиль и настройки                               |
| `/install/`              | Инструкция установки на экран «Домой»              |

Неавторизованный пользователь на любом экране уводится на `/login/` с
возвратом обратно (`?next=`), включая `/invite/`.

### 6.3. Данные и синхронизация

- **RTK Query** — единственный способ ходить на API. Теги: `Me`, `Friends`,
  `Requests`, `Timers`, `Timer`, `Waits`, `Stats`.
- `baseQueryWithReauth`: на 401 один раз обновляет access по refresh
  (с мьютексом — параллельные запросы ждут одно обновление), при провале —
  logout и `/login/`.
- Токены — в `localStorage` (фронт и API на разных доменах, сторонние
  cookie Safari режет). Гидрация до первого запроса, как `CartHydrator` в
  divodivnoe.
- **Щелчок тумблера — оптимистичный.** `onQueryStarted` сразу пишет новое
  состояние в кэш, ручка уезжает без ожидания сети; при ошибке — откат,
  при 409 — подстановка присланного сервером состояния.
- **Живость без WebSocket:** экран таймера опрашивает `GET /timers/<id>`
  каждые 5 с, пока вкладка видима (`pollingInterval` +
  `skipPollingIfUnfocused`), плюс `refetchOnFocus` / `refetchOnReconnect`.
  Service worker при получении пуша шлёт открытым окнам `postMessage`, и
  окно инвалидирует тег `Timer` — второй участник видит щелчок почти сразу.
  Опрос дешёвый: ответ ~300 байт. SSE — только если опроса окажется мало.
- **Время.** Таймер тикает на клиенте от `started_at` с поправкой на
  смещение часов: каждый ответ API несёт `server_time`, клиент хранит
  `offset = server_time − Date.now()`. Тики **не** идут через Redux:
  секунды обновляет изолированный компонент `Elapsed`, остальной экран не
  перерисовывается.
- Нет сети — ручка заблокирована, плашка «Нет связи», последнее известное
  состояние на экране.

### 6.4. Анимации (framer-motion)

Цель — ощущение физической вещи: тумблер щёлкает, как настоящий, а экран
при этом не тормозит на дешёвом Android.

**Как подключать**

- `LazyMotion` с `domAnimation` на уровне `AppProviders` и компоненты `m.*`
  вместо `motion.*` — стартовый вес библиотеки ~5 КБ вместо ~34 КБ.
  `domMax` (drag, layout) подгружается динамическим импортом только на
  экране таймера, где нужен свайп ручки.
- `MotionConfig reducedMotion="user"` — при системной настройке
  «Уменьшить движение» анимации гаснут до мгновенных смен.
- Пресеты пружин лежат в `lib/motion/presets.ts` и используются везде
  одни и те же — ни одной «магической» `stiffness` в компонентах.
- Анимируются **только `transform` и `opacity`**. Не анимировать
  `width`, `height`, `top`, `left`, `box-shadow`, `filter: blur` — это
  перерисовка на каждом кадре.

**Что анимируется**

| Где              | Анимация                                                                 |
| ---------------- | ------------------------------------------------------------------------ |
| Ручка тумблера   | Пружина к позиции (`stiffness ≈ 500, damping ≈ 32`), лёгкий overshoot; при свайпе — `drag="x"` с `dragConstraints` и `dragElastic`, прилипание к ближайшей позиции по скорости и положению |
| Нажатие          | `whileTap` — ручка сжимается до `scale 0.94`; `navigator.vibrate(10)` где есть |
| Подложка тумблера| Цветная заливка стороны ждущего «перетекает» за ручкой через `useTransform` от `x` ручки — без отдельного стейта |
| Имена сторон     | Активное имя — `scale 1.08` и полная непрозрачность, неактивное — 0.5    |
| Таймер           | Смена цифры — только изменившаяся цифра уезжает вверх (`AnimatePresence mode="popLayout"`), остальные стоят |
| Старт ожидания   | Таймер появляется из центра (`opacity + y + scale`), «Никто не ждёт» уходит |
| Тосты («Отменить», 409) | Выезд снизу пружиной, закрытие свайпом вниз                        |
| Смена экранов    | Короткий fade + сдвиг 8 px, ≤ 200 мс; назад — зеркально                   |
| Списки           | Появление элементов со `stagger` 30 мс, только при первом показе          |
| Счёт в истории   | Полоски «кто сколько ждал» растут через `scaleX` от 0                     |
| Форма входа      | Неверный пароль — горизонтальная «тряска» поля; переключение «Вход / Регистрация» — поле имени плавно раскрывается |

**Бюджет**

- Анимации держат 60 fps на Android среднего класса (проверка —
  Performance в Chrome с 4× CPU throttling).
- Ни одна анимация интерфейса не длиннее 350 мс, кроме пружины ручки,
  которая заканчивается сама.
- Анимация никогда не задерживает действие: запрос уходит в момент тапа, а
  не по окончании анимации.

### 7.4. Логика переключения

`switch(timer, actor, waiting_for, version)` в одной транзакции с
`select_for_update()` на таймере:

1. `actor` — участник таймера, иначе 404 (не 403: чужой id не должен
   подтверждать существование).
2. `version` не совпал → 409 + текущее состояние.
3. Состояние не меняется (`left` → `left`) → 200 без изменений,
   идемпотентно.
4. Есть открытое ожидание → закрыть: `ended_at = now`, `duration`,
   `ended_by = actor`, `end_reason = stopped | switched`.
5. `waiting_for ≠ none` → открыть новое `Wait`.
6. `state = waiting_for`, `version += 1`.
7. `on_commit` → пуши обоим участникам на все устройства, кроме
   `device_id` щелчка.

`undo(timer, actor, wait_id)`: ожидание — последнее, начато `actor`,
прошло ≤ `undo_seconds`. Ожидание помечается `undone`, если оно
закрыло предыдущее переключением — предыдущее **открывается обратно**
(возвращаем `ended_at = null`), состояние таймера возвращается,
`version += 1`, пуш «Отменено» по тем же правилам.

### 7.5. Периодика

Контейнер `wait-proof-tick` (тот же образ, `python manage.py tick --loop`)
раз в минуту делает:

- напоминания: открытые ожидания, где с `max(started_at, last_reminder_at)`
  прошло ≥ `reminder_minutes`;
- автозакрытие ожиданий старше `auto_close_hours`;
- чистка `PushLog` старше 30 дней, blacklist
  JWT (`flushexpiredtokens`) — раз в сутки.

Команда идемпотентна и безопасна при наложении запусков (блокировка
`select_for_update(skip_locked=True)`).

### 7.6. API

База `/api/v1`, JSON, авторизация `Authorization: Bearer <access>`. Каждый
ответ ручек таймера несёт `server_time`. Ошибки — `{"detail": "..."}` с
текстом, который можно показать пользователю как есть.

**Вход**

```
POST   auth/register             {email, password, name}  → 201 {access, refresh, user}
POST   auth/login                {email, password}    → {access, refresh, user}
POST   auth/refresh              {refresh}            → {access, refresh}
POST   auth/logout               {refresh}            → 204   (refresh в blacklist)
GET    me                                             → user
PATCH  me                        {name, timezone, notify_*}
POST   me/invite-code/rotate                          → {invite_code, invite_url}
POST   me/password               {old_password, new_password}  → {access, refresh}
POST   me/delete                 {password}           → 204
```

**Друзья**

```
GET    friends                                        → [{id, name, email, since, timer_id}]
DELETE friends/<user_id>                              → 204
GET    friends/requests                               → {incoming: [...], outgoing: [...]}
POST   friends/requests          {email}              → 202 (одинаково для любой почты)
POST   friends/requests/<id>/accept   → friend
POST   friends/requests/<id>/decline  → 204
DELETE friends/requests/<id>          → 204 (отмена своей)
POST   friends/invite            {code}               → friend  (дружба сразу)
```

**Таймеры**

```
GET    timers                                         → [timer]
POST   timers                    {friend_id, left: "me"|"friend", left_label, right_label}
GET    timers/<id>                                    → timer
PATCH  timers/<id>               {left_label, right_label, reminder_minutes}
POST   timers/<id>/swap-sides                         → timer
POST   timers/<id>/switch        {waiting_for: "left"|"right"|"none", version}
                                                      → 200 timer | 409 {detail, timer}
POST   timers/<id>/undo          {wait_id}            → timer
GET    timers/<id>/waits?cursor=                      → {results, next}
GET    timers/<id>/stats?period=week|month|all        → stats
DELETE timers/<id>                                    → 204 (в архив)
```

Пример `timer`:

```json
{
  "id": 12,
  "left":  {"user_id": 7, "name": "Катя", "label": "Она"},
  "right": {"user_id": 3, "name": "Дима", "label": "Он"},
  "state": "left",
  "version": 41,
  "current_wait": {
    "id": 318,
    "started_at": "2026-09-16T15:40:02Z",
    "started_by": 3,
    "undo_until": "2026-09-16T15:40:12Z"
  },
  "reminder_minutes": 15,
  "server_time": "2026-09-16T16:03:43Z"
}
```

Пример `stats`:

```json
{
  "period": "week",
  "left":  {"waited_seconds": 2820,  "times": 2, "avg_seconds": 1410, "max_seconds": 2100},
  "right": {"waited_seconds": 11520, "times": 5, "avg_seconds": 2304, "max_seconds": 4380}
}
```

Здесь `left.waited_seconds` — сколько **ждал** левый участник. Границы
недели и месяца считаются в часовом поясе запросившего пользователя.

**Пуши и служебное**

```
GET    push/config                                    → {vapid_public_key}
POST   push/subscriptions        {device_id, endpoint, keys: {p256dh, auth}, user_agent}
DELETE push/subscriptions        {endpoint}
GET    push/subscriptions                             → устройства пользователя
POST   push/test                                      → отправить себе проверочный пуш
GET    config                                         → {poll_interval_seconds, undo_seconds}
GET    health                                         → {ok: true} (проверяет базу)
```

`switch` и `undo` принимают заголовок `X-Device-Id` — это устройство не
получает пуш о собственном щелчке.

Регистрация на занятую почту отвечает «Эта почта уже зарегистрирована» —
для приложения на двоих удобство важнее, чем скрыть факт регистрации.

**Лимиты (ScopedRateThrottle)**: `login` 10/мин на IP и 5 неудачных попыток
за 15 минут на почту, `register` 5/час на IP,
`friends_request` 20/час, `switch` 30/мин, остальное 120/мин. Счётчики
лежат в `DatabaseCache` (без Redis), чтобы все воркеры считали вместе.

### 7.7. Админка

Разделы в порядке работы (как `common/admin.py` в k30):

- **Пользователи** — поиск по почте/имени, смена пароля (так решается
  «забыл пароль»), друзья, таймеры, устройства,
  «Отправить тестовый пуш».
- **Таймеры** — участники, текущее состояние, инлайн последних ожиданий,

- **Ожидания** — фильтры по таймеру, причине закрытия, `counts`; правка

- **Дружба**, **Заявки в друзья**.
- **Push-подписки**, **Журнал пушей** — с кодом ответа и ошибкой.
- **Настройки** — тексты пушей, автозакрытие, отмена, опрос.

Все поля и модели — с `verbose_name` по-русски.

- `SECRET_KEY`, `VAPID_PRIVATE_KEY`, пароль базы — только в

- `manage.py check --deploy` без ошибок, HSTS, secure cookies для админки.
- Пользователь видит только свои таймеры, друзей и заявки; чужой id — 404.

- `ci.yml` проверяет, что экспорт не пустой: `out/index.html`,
  `out/timer/index.html`, `out/sw.js`, `out/manifest.webmanifest` на месте.
- Разово: **Settings → Pages → Source: GitHub Actions**.
- `next.config.ts`: `output: 'export'`, `trailingSlash: true`,
  `reactCompiler: true`, `images.unoptimized`, `basePath` из
  `NEXT_PUBLIC_BASE_PATH` = `/wait-proof`.
- basePath обязательно учитывается в `manifest.start_url`, `scope`,
  регистрации SW и `data.url` пушей — иначе установка на iOS откроет 404.
- Переменные репозитория (Settings → Secrets and variables → Actions →
  Variables): `API_URL` = `https://168-222-142-117.sslip.io/api/v1`
  (необязательно — это значение по умолчанию). Публичный VAPID-ключ фронт
  берёт из `GET /config`, чтобы ключ сборки и ключ сервера не могли разойтись.

### 8.2. Бэкенд → VPS 168.222.142.117, рядом с Формой

**Что уже есть на сервере** (по репозиторию `forma`): Docker Compose в
`/opt/forma` — `postgres`, `django`, `nextjs` и `nginx`. Контейнер
`forma-nginx-1` занимает порты **80 и 443**, отдаёт `forma-one.ru`. RAM —
1,9 ГБ, поэтому Форма собирает образы в CI. Деплой Формы заходит на сервер
**под root по паролю** — это остаётся как есть.

Отсюда решения:

- **Свой nginx не ставим** — порты заняты. Наружу API отдаёт nginx Формы:
  в его конфиг добавляется один `server` для `168-222-142-117.sslip.io`,
  который проксирует в контейнер `wait-proof-api` через общую docker-сеть
  `edge`. Правка вносится в репозиторий Формы и выкатывается её же
  пайплайном (раздел 8.4).
- **Своя база в своём контейнере**, не в Postgres Формы: разные бэкапы,
  обновления и пароли, авария одного проекта не задевает другой.
- **Ничего не собираем на сервере** — образ `ghcr.io/eugenepokalyuk/wait-proof-api`
  собирается в Actions.
- **Жёсткие лимиты памяти** на каждый контейнер, чтобы «Я тебя жду» не
  могло съесть память Формы.

`deploy/docker-compose.prod.yml`:

| Сервис             | Образ                      | Что делает                                    | RAM / CPU |
| ------------------ | -------------------------- | --------------------------------------------- | --------- |
| `wait-proof-db`    | `postgres:16-alpine`       | база; `shared_buffers=32MB`, `max_connections=20`, том `wait_proof_pg` | 128 МБ / 0.5 |
| `wait-proof-api`   | `wait-proof-api:<sha>`     | gunicorn gthread, 1 воркер × 4 потока (нагрузка — пара человек), порт 8000 **только в сети**, наружу не публикуется | 200 МБ / 0.5 |
| `wait-proof-tick`  | тот же образ               | `manage.py tick --loop`: напоминания, автозакрытие, чистка | 100 МБ / 0.25 |
| `wait-proof-backup`| `postgres:16-alpine`       | раз в сутки `pg_dump -Fc` в `/var/backups/wait-proof`, хранит 14 дней | 32 МБ / 0.25 |
| `wait-proof-certbot`| `certbot/certbot`         | раз в 12 ч `certbot renew`, хук копирует сертификат в `/opt/edge/certs/wait-proof/` | 64 МБ / 0.25 |

Итого не больше ~530 МБ даже в пике. Если контейнер упрётся в лимит, ядро
убьёт **его**, а не процессы Формы.

Сети: `internal` (своя, база видна только нашим контейнерам) и `edge`
(внешняя, общая с nginx Формы; в неё входит только `wait-proof-api`).
Все контейнеры — `restart: unless-stopped`, у `api` и `db` есть
`healthcheck`. В compose-файле явно `name: wait-proof` — все команды
`docker compose` действуют только на наш проект.

#### Гарантии для Формы

Форма не должна лечь — это требование важнее сроков и удобства.

**Никогда не делаем на сервере:** не меняем пароли, настройки ssh,
файрвол; не ставим и не обновляем пакеты (`apt upgrade` может перезапустить
Docker, а с ним и Форму); не перезапускаем демон Docker; не запускаем
`docker system prune`, `docker volume prune`, `docker network prune`; не
заходим в `/opt/forma` руками и ничего туда не кладём (деплой Формы делает
там `git clean`); не публикуем порты наружу.

**Правка nginx Формы — одна, через её же репозиторий и пайплайн**, и
устроена так, чтобы nginx поднимался в любом состоянии нашего проекта:

1. **Файл сертификата существует всегда.** nginx смотрит на
   `/opt/edge/certs/wait-proof/{fullchain,privkey}.pem`. При подготовке
   сервера туда кладётся временный самоподписанный сертификат, потом
   certbot своим хуком подменяет его настоящим. Отсутствующий файл
   сертификата — самая частая причина, по которой nginx не стартует; здесь
   её нет.
2. **Прокси через переменную и `resolver 127.0.0.11`:**

   ```nginx
   resolver 127.0.0.11 valid=10s ipv6=off;
   set $wait_proof http://wait-proof-api:8000;
   location / { proxy_pass $wait_proof; ... }
   ```

   С обычным `proxy_pass http://wait-proof-api:8000` nginx Формы **не
   запустится**, если нашего контейнера нет. С переменной он стартует
   всегда, а наш адрес просто отвечает 502.
3. **Сеть `edge` создаётся до правки Формы** — иначе `docker compose up`
   Формы не найдёт внешнюю сеть.
4. **Проверка конфига до любых изменений.** В деплой Формы первым шагом,
   ещё до пересоздания её контейнеров, добавляется
   `docker compose -f docker-compose.prod.yml run --rm --no-deps nginx nginx -t`.
   Если конфиг битый — деплой красный, работающие контейнеры Формы не
   тронуты. Эта проверка защищает Форму и от её собственных будущих ошибок.
5. **Откат** — revert этого коммита в `forma-project`, пайплайн вернёт
   прежний nginx. Готовый фрагмент конфига и текст PR лежат в
   `deploy/forma/`.
6. Выкатывать правку Формы в тихое время и сразу проверять `forma-one.ru`.
   Пересоздание nginx — это ~1–3 секунды недоступности, ровно как при
   каждом обычном деплое Формы.

**Пайплайн `deploy-api.yml`**

1. `build`: собрать `api/Dockerfile`, запушить в GHCR с тегами `latest` и
   `<sha>` (кэш `type=gha`). Пакет GHCR — публичный (секретов в образе нет).
2. `deploy`: ssh под пользователем `waitproof` по ключу →
   `IMAGE_TAG=<sha> bash -s < deploy/deploy.sh` (скрипт по stdin, чтобы
   `git reset` не перезаписывал его на ходу). Секреты: `DEPLOY_SSH_KEY`,
   `DEPLOY_HOST`, `DEPLOY_KNOWN_HOSTS`. `concurrency: deploy-api`, без
   отмены идущего.
3. `deploy.sh` на сервере:
   `cd /opt/wait-proof` → `git fetch` + `git reset --hard origin/main`
   (репозиторий публичный — ключ не нужен) →
   `docker compose pull` → `docker compose run --rm wait-proof-api python manage.py migrate --noinput` →
   `docker compose run --rm wait-proof-api python manage.py createcachetable` →
   `docker compose up -d --remove-orphans` → чистка старых образов **только
   своего проекта** (`docker image prune -f --filter label=project=wait-proof`;
   чужие образы Формы не трогаем).
4. Проверка с раннера: `https://168-222-142-117.sslip.io/api/v1/health`
   отвечает 200 в течение 60 с — так проверяется вся цепочка, включая nginx
   Формы. Иначе — логи `docker compose logs --tail 80` и красный деплой.

Откат — Run workflow на нужном коммите: образ с тегом `<sha>` уже в GHCR.

**HTTPS.** Фронт на https, браузер не пустит запросы на http. Своего
домена нет, поэтому имя `168-222-142-117.sslip.io` (резолвится в IP
сервера) и сертификат Let's Encrypt. Выпуск и продление — `certbot` в
режиме webroot, файлы лежат на хосте в `/opt/edge/letsencrypt` и
`/opt/edge/certbot-www` и примонтированы в nginx Формы только на чтение.
Продление — контейнер `wait-proof-certbot` в нашем compose: раз в 12 часов
`certbot renew`, хук копирует новый сертификат в `/opt/edge/certs/wait-proof/`.
Перечитывает его nginx Формы по `nginx -s reload` — это мягкая команда:
при ошибке в конфиге nginx продолжает работать со старым. Reload делает
строка в crontab пользователя `waitproof` раз в сутки (наш деплой nginx
Формы не трогает вовсе):
`docker exec forma-nginx-1 nginx -s reload`. Сокет Docker в контейнер
certbot не пробрасываем — это был бы root на хосте. `nginx -s reload` —
единственное, что мы вызываем у контейнера Формы.

### 8.3. Почта

**В первой версии почта не используется**: вход по паролю, писем нет,
`EMAIL_*` не заполняются.

Когда появится ящик:

- свой почтовый сервер на VPS — **нет**: без своего домена (DNS у sslip.io
  не наш) нельзя настроить SPF, DKIM, DMARC, и Gmail с Яндексом письма не
  примут. Плюс лишний процесс на сервере Формы;
- отдельный ящик Gmail под проект с паролем приложения:
  `EMAIL_HOST=smtp.gmail.com`, `EMAIL_PORT=587`, `EMAIL_USE_TLS=True`;
  лимит ~500 писем в сутки — с огромным запасом. Запасной — Яндекс
  (`smtp.yandex.ru:465`, SSL);
- тогда добавить подтверждение почты и сброс пароля кодом (п. 4.1).

### 8.4. Первичная подготовка сервера (`deploy/bootstrap.md`)

Единственный раз, когда на сервер заходят руками, — подготовить его к
приёму деплоев. Код при этом не копируется: сервер клонирует публичный
репозиторий с GitHub, дальше всё делает пайплайн. Пароли, ssh и файрвол
не меняются. Каждый шаг — только добавление нового рядом с Формой.

1. **Осмотр, ничего не меняя.** `docker compose ls`, `docker ps`,
   `free -m`, `df -h`, `ss -tlnp`, версия Docker и Compose, есть ли свободные
   ~800 МБ RAM и ~3 ГБ диска. Если памяти меньше — **стоп**, обсуждаем до
   любых действий.
2. **Снимок Формы.** `pg_dump` её базы, копии `/opt/forma/.env.prod` и
   `/opt/forma/certs/` в `/root/forma-backup-<дата>`. Проверить:
   `forma-one.ru` открывается.
3. Пользователь `waitproof` в группе `docker`, в его `authorized_keys` —
   ключ GitHub Actions (добавление ключа новому пользователю ничего не
   меняет для root и Формы). Если `sshd -T` показывает, что вход по ключу
   выключен, — sshd не трогаем, деплой ходит так же, как Форма, а
   секреты в Actions называются `DEPLOY_USER` / `DEPLOY_PASSWORD`.
4. `docker network create edge`.
5. Каталоги: `git clone https://github.com/eugenepokalyuk/wait-proof.git /opt/wait-proof`
   (владелец `waitproof`), `/etc/wait-proof/api.env` (600),
   `/opt/edge/certbot-www`, `/opt/edge/letsencrypt`,
   `/opt/edge/certs/wait-proof/` с **временным самоподписанным
   сертификатом**, `/var/backups/wait-proof` (700).
6. Заполнить `/etc/wait-proof/api.env`: `SECRET_KEY`, VAPID-ключи, пароль
   базы, `CORS_ALLOWED_ORIGINS`, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`.
7. Первый деплой — Actions → Deploy API → Run workflow. Контейнеры
   поднимутся, но снаружи API пока недоступен — это нормально.
   `docker exec -it wait-proof-api python manage.py createsuperuser`.
8. **Одна правка Формы** (PR в `forma-project`, выкатывается её
   пайплайном) — всё из «Гарантий для Формы»: проверка `nginx -t` первым
   шагом деплоя, nginx входит в сеть `edge`, монтирует `/opt/edge/*` на
   чтение, два `server`-блока для `168-222-142-117.sslip.io` (80 — ACME и
   редирект, 443 — прокси через переменную). Сразу проверить `forma-one.ru`.
9. Выпустить настоящий сертификат (`docker compose run --rm wait-proof-certbot certonly --webroot …`),
   хук подменит временный, `nginx -s reload`. Добавить строку reload в
   crontab пользователя `waitproof`.
10. Финальная проверка: `forma-one.ru` работает, деплой Формы зелёный,
    `https://168-222-142-117.sslip.io/api/v1/health` = 200, `/admin/`
    открывается, `free -m` показывает запас памяти. Контрольный тест:
    `docker compose -p wait-proof stop wait-proof-api` → Форма работает,
    наш адрес отвечает 502 → `start` обратно.

## 10. Критерии приёмки

- [ ] Регистрация и вход по паролю на iPhone в Safari и в установленном
      приложении; связка ключей предлагает сохранить и подставить пароль.
- [ ] Друг добавляется ссылкой за три тапа.
- [ ] Щелчок на телефоне А → ручка на телефоне Б переезжает ≤ 5 с при
      открытом приложении, пуш на Б приходит ≤ 5 с при закрытом.
- [ ] Перезагрузка, выход из приложения, смена телефона не сбрасывают таймер;
      показанное время расходится с серверным не больше чем на 1 с.
- [ ] Одновременный щелчок с двух телефонов не создаёт двух открытых ожиданий.
- [ ] «Отменить» в течение 10 с убирает ожидание из счёта и возвращает
      предыдущее состояние.
- [ ] Забытое ожидание закрывается через 12 ч и в счёт не идёт.
- [ ] Напоминания приходят с выбранным интервалом и прекращаются после снятия.
- [ ] Отписанное устройство (404/410) удаляется, пуши на остальные доходят.
- [ ] Показатели производительности и анимаций из п. 6.4 и 6.7.
- [ ] `prefers-reduced-motion` отключает анимации.
- [ ] Любое переключение и отмена присылают пуш обоим участникам на все
      устройства, кроме того, с которого щёлкнули.
- [ ] Форма не пострадала: `forma-one.ru` работает, деплой Формы зелёный,
      nginx Формы поднимается даже при остановленном `wait-proof-api`,
      битый `nginx.conf` останавливает деплой Формы до пересоздания контейнеров.
- [ ] Мерж в `main` сам выкатывает прод: правка в `web/` — только Pages,
      в `api/` — только сервер; упавший бэк даёт красный деплой.
- [ ] README и `api/docs/` в репозитории — в стиле divodivnoe и k30-api:
      как запустить, как устроено и почему.

## 11. Не входит в первую версию

Таймеры на троих и больше, несколько таймеров на одну пару, чат,
комментарии к ожиданиям, оспаривание записей пользователями, свои цвета

почты и сброс пароля — когда появится ящик).

## 13. Правила репозитория

- Автор каждого коммита — владелец репозитория, имя и почта из его
  локальной настройки git. В коммитах, PR, комментариях к коду, README и
  документации нет трейлеров `Co-Authored-By`, подписей генераторов и
  упоминаний сторонних инструментов.
- Прод обновляется только из `main` и только пайплайном. На сервер руками
  не копируется код и не правятся файлы проекта; исключение — разовая
  подготовка из п. 8.4.
- Секреты не коммитятся: реальные значения только в `/etc/wait-proof/api.env`
  на сервере и в секретах GitHub Actions; в репозитории — `.env.example`.
- Личные файлы IDE и локальных инструментов исключаются через
  `.git/info/exclude`, а не через общий `.gitignore`.
